# 特征比对器

课堂演示程序：把叶片的特征变成数字，再比较谁更像谁。

**在线地址：https://raidenlumine.github.io/feature-comparator/**

电脑、手机、平板都能打开，不用装任何东西。微格教室的电脑也只要打开浏览器输入网址即可。

---

## 两种使用方式

### 方式一：在线（推荐，最省事）

打开浏览器，输入：

```
raidenlumine.github.io/feature-comparator
```

**注意**：需要联网。如果教室网络不通，用方式二。

> 如果双击后一片空白或图片不显示，说明浏览器把本地文件限制了。
> 换 Chrome 或 Edge 打开即可（Windows 自带 Edge）。

## 演示脚本（约 90 秒）

### 第 1 步 · 正常识别（默认状态）

> 「这是甲。机器看到的是三个数字：0.44、0.65、0.40。
> 跟参考库里甲的数字比，距离最近，所以判为甲——相似度 87%。」

### 第 2 步 · 只留颜色 ← 整节课的转折

按 **2** 切到「逆光照片」，再按 **Q**、**E** 关掉轮廓和纹理。

结果翻转：**判为乙，59%**。

> 「现在只让机器看颜色。可这张照片是逆光的，颜色偏了——
> 它很有把握地说是乙。**它认错了。**
> 错不是因为机器笨，是因为我们只给了它一个不可靠的证据。」

### 第 3 步 · 把证据给全

再按 **Q**、**E** 打开。变回甲，但只有 **58%**。

> 「证据给全了，它认对了——但只领先 16 个百分点。
> 所以机器给的从来不是『正确答案』，是『最像的那个』。」

### 第 4 步 · 再退一步

按 **W** 关掉颜色。两者各占一半 —— **50% / 50%**。

> 「如果纹理这一项也用不上，两者各占一半，机器只能猜。」

### 第 5 步 · 照卡片填（配合纸质卡片）

学生填完桌面的「植物特征卡」后，按 **M** 进入手动模式，按学生的勾选逐项点击。

> 「这三位同学写的是：叶缘有锯齿、浅绿、叶脉密。
> 我把它们点进去——机器读到的是 0.78、0.72、0.42，判为乙。」

**这一步是全课的关键**：学生亲眼看到，自己写在纸上的话，被翻译成了机器能读的数字。

如果不同学生填出不同组合，可以逐个输入，让他们看结果怎么变：

| 卡片组合 | 机器读数 | 结果 |
|---|---|---|
| 光滑 · 深绿 · 疏 | 0.44 / 0.65 / 0.40 | 甲 87% |
| 锯齿 · 浅绿 · 密 | 0.78 / 0.72 / 0.42 | 乙 87% |
| 光滑 · 浅绿 · 疏 | 0.44 / 0.72 / 0.40 | 甲 76% |
| 锯齿 · 深绿 · 密 | 0.78 / 0.65 / 0.42 | 乙 76% |

> 「同样是甲，为什么有的 87%、有的 76%？因为你给机器的证据不一样。」

### 第 6 步 · 收束到课后任务

> 「那你们回去拍的照片，会不会也像这样？
> 找两种最像的植物，看它会不会认错——这就是课后任务。」

## 三个特征是怎么算的

| 特征 | 计算方式 | 含义 |
|---|---|---|
| 轮廓 | 叶子轮廓的 周长² ÷ 面积 | 锯齿越多，值越大 |
| 颜色 | 叶面平均亮度 | 越深绿，值越大 |
| 纹理 | 叶面灰度标准差 | 叶脉越密，值越大 |

三个数拼成一个向量，待识别样本与参考库逐个算**欧氏距离**，距离最近者为「最像」，
再按距离反比归一化得到相似度百分比。

数值取自真实拍摄的两片叶子，不是编的。

## 可能被问到的问题

**「这是深度学习吗？」**
不是。这是最朴素的特征比对（模板匹配），三个特征还是人手设计的。
真实的识别系统里，特征不是人算的，是神经网络从大量图片里自己学出来的——下节课会用到预训练模型。

**「为什么甲、乙的数值是固定的？」**
因为它们代表参考库里已经录入的样本。真实系统里这个"参考库"就是训练数据。
课堂上只演示比对这一步，不演示录入和训练。

**「相似度为什么会变？」**
关掉某些特征后，参与比较的维度变少了，两个候选的距离差随之变小，
归一化之后百分比就接近了。这正是"证据不足 → 判断不可靠"的数学表达。

## URL 参数（排练时直达某一幕）

在线和本地都支持：

| 场景 | 参数 |
|---|---|
| 正确识别 | `?s=s1&f=111` |
| 只开颜色（认错） | `?s=s2&f=010` |
| 三特征全开（勉强认对） | `?s=s2&f=111` |
| 两者分不出 | `?s=s2&f=011` |
| 手动填卡 | `?m=1` |
| 手动 + 指定选项 | `?m=1&c=serrated,light,dense` |

- `s`：`s1` 正常拍摄 / `s2` 逆光照片 / `s3` 另一株植物 / `s4` 抖动失焦
- `f`：三位，分别对应 轮廓、颜色、纹理，`1` 开 `0` 关
- `c`：三位，分别对应 轮廓、颜色、纹理 的选项（`smooth`/`serrated`、`dark`/`light`、`sparse`/`dense`）

例如在线直接跳到认错那一幕：

```
https://raidenlumine.github.io/feature-comparator/?s=s2&f=010
```

## 目录结构

```
Recognizer/
├── index.html              页面入口
├── css/
│   └── style.css           全局样式（画布铺满、禁止滚动）
├── js/
│   ├── config.js           画布尺寸、配色、布局参数
│   ├── data.js             特征向量、样本定义、素材路径
│   ├── engine.js           距离计算与结果判定（纯逻辑，不碰 DOM）
│   ├── render.js           Canvas 绘制（图形、文字、面板、手动填卡）
│   └── app.js              状态管理、图片预加载、事件绑定
└── assets/                 6 张叶片素材（透明底 PNG）
```

课堂用的植物特征卡在上层目录：`备赛资料/植物特征卡.pdf`（A4，每页 2 张）。

各层职责单一，改配色只动 `config.js`，改算法只动 `engine.js`，改布局只动 `render.js`。
